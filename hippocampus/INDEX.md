# 海马体 (Hippocampus) — AI 入口索引

> 跨会话偏好记忆层。数据库结构详见 `DB_SCHEMA.md`。
> 数据库文件：`hippocampus/memory.db`（SQLite，WAL 模式）

## MCP 工具速查

| 工具                      | 用途                       | 关键参数                                                          |
| ------------------------- | -------------------------- | ----------------------------------------------------------------- |
| `hippocampus_search`      | 检索历史偏好               | `query`（关键词）, `platform`, `top_k`                            |
| `hippocampus_add`         | 写入新记忆                 | `content`, `platform`, `dimension`, `signal_level`, `memory_type` |
| `hippocampus_get_weights` | 查看各平台×维度的权重摘要  | —                                                                 |
| `hippocampus_forget`      | 删除指定记忆               | `entry_id`                                                        |
| `hippocampus_reset`       | 清空所有记忆（需二次确认） | —                                                                 |

> ⚠️ 调用 `hippocampus_*` 前，先用 `activate_memory_management_tools` 激活工具组。

## 信号级别（`signal_level`）

决定何时写入记忆及初始权重：

|    级别     | 触发条件                            | 初始权重  | AI 行为                      |
| :---------: | ----------------------------------- | :-------: | ---------------------------- |
|  🔴 `high`  | 用户显式修正（"不对，应该是…"）     |     2     | 自动写入                     |
| 🟡 `medium` | 深度追问某方向 / 采纳某选项进入执行 |     1     | 提议写入，用户确认后执行     |
|  ⚪ `weak`  | 沉默 / 话题漂移                     |     —     | **不写入**（MCP 层直接拒绝） |
|   ❌ 标注   | 压力或妥协情境下的选择              | 同 medium | 写入但标注（降权提示）       |

## 记忆类型（`memory_type`）

| 类型                    | 用途                   |    启动注入    |
| ----------------------- | ---------------------- | :------------: |
| `user_preference`       | 用户技术偏好（默认）   |    ✅ 始终     |
| `coding_principle`      | 编码原则与最佳实践     |    ✅ 始终     |
| `maintenance_checklist` | 框架维护清单           | 仅框架内部话题 |
| `architecture_decision` | 架构决策记录 (ADR)     | 仅框架内部话题 |
| `known_issue`           | 已知问题/限制/规避方案 | 仅框架内部话题 |

> **设计原则**：`user_preference` 和 `coding_principle` 高频注入避免遗漏；后三类是低频维护信息，仅在框架内部话题时关注。

### 知识库维护记忆的类型约束

由 References 知识库扩充（QG-2 写入新文档）触发的 hippocampus 记录必须满足：

- **`memory_type`**：必须用 `architecture_decision`，**禁止**使用 `user_preference`
- **`dimension`**：必须以 `知识库` 开头（如 `知识库维护`、`知识库 文档管理`），与用户技术偏好维度明确区分
- **原因**：此类记忆属于框架维护行为，不是用户决策偏好。使用 `user_preference` 会污染检索结果——当 `hippocampus_search` 按关键词匹配时，技术偏好和知识库维护日志混在一起，浪费 top_k 名额

## 内容结构规范（`content` 字段）

> **核心原则**：三年后 AI 读到这条记忆，能否据此还原你当时的判断逻辑？不能就别写。

写入 `content` 时使用**锚点+自由叙述**格式——字段标签作为锚点（供 parser 校验），字段值保持自然语言表达。

### 字段锚点

```
排除: <被排除的替代方案及排除原因，自由叙述>
选择: <最终决策>
情境: <决策背景：团队规模、时间约束、技术栈上下文等>
失效条件: <什么可观测事件会使该偏好失效>
```

| 锚点 | 是否必填 | 说明 |
|------|:--------:|------|
| `排除:` | 推荐 | 记录了「为什么不选 B」的记忆复用价值远高于只记录「选了 A」。包含方案名 + 排除原因，不只是列举名称 |
| `选择:` | 推荐 | 记录最终决策，非单纯偏好声明——要有具体方案描述 |
| `情境:` | 推荐 | 帮助未来判断：决策时的团队规模、时间约束、已有技术栈等背景 |
| `失效条件:` | **必填** | 必须声明偏好的边界——什么可观测事件发生时应重新评估 |

> ⚠️ **「失效条件」不允许留空**。如果暂时想不清楚边界，写诚实占位：`失效条件: 暂不明确，需在实际使用中观察后补充`。这样 AI 检索时会知道这个偏好的边界还没想清楚，而非把它当成永久性结论。

### 校验规则（MCP 层）

`hippocampus_add` 写入前自动校验：

| 条件 | 行为 | 含义 |
|------|:----:|------|
| `失效条件:` 锚点缺失 | **block** | 拒写，必须补充 |
| `失效条件:` 锚点存在但值为空 | **block** | 拒写，至少写占位词 |
| `排除:` / `选择:` 锚点缺失 | warning | 写成功但提示补充 |
| `排除:` 存在但值过短（< 10 字） | warning | 只有名称没有原因，建议补充 |

### 示例

✅ **好的记忆**：
```
排除: TCA 和 VIPER。TCA 依赖 Composable Architecture，
      和现有代码耦合方式不兼容，迁移成本超过收益；
      VIPER 样板代码太多，两人小团队维护成本不合理。
选择: MVVM + Combine
情境: iOS 项目，2人团队，已有 UIKit 存量代码，6周交付压力
失效条件: 团队扩展到5人以上且有专职架构师时重新评估
```

❌ **不完整的记忆**：
```
排除: TCA, VIPER       ← 只列举了名称，没有排除原因
选择: MVVM              ← 缺少具体方案描述
情境: 无特别情境          ← 情境为空，无法判断适用边界
失效条件:               ← 空值，会被 block
```
