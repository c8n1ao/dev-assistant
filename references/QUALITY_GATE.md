# Quality Gate & Conventions

> 本文档定义 References 知识库的质量门规则和编号约定。
> 所有规则以 `QG-{序号}` 编号，在讨论中可通过编号引用。

---

## QG-1 写入决策触发条件

当 AI 回答涉及 INDEX.md 无匹配的领域，且**同时满足以下全部条件**时，启动写入流程：

1. 该主题**可能再次被问到**（非一次性问题）
2. 有明确的「正确答案」或**可验证的领域共识**（非纯观点/偏好）
3. 内容不重复已有文档
4. 内容具有**参考复用价值**（适用于多个场景/项目）

不满足以上任一条件时，不启动写入流程。

---

## QG-2 五步写入流程

```
AI 回答涉及 INDEX.md 无匹配领域
        │
        ▼
┌───────────────────────────────┐
│ 1. 判断：是否满足 QG-1 条件？  │
└───────────────┬───────────────┘
                │ 满足
                ▼
┌───────────────────────────────────────┐
│ 2. AI 生成候选条目（草稿）             │
│ 包含：完整 frontmatter + 正文          │
│       + keywords (中英双语, 5-15 个)   │
│ 附：credibility 自评及理由             │
└───────────────┬───────────────────────┘
                │
                ▼
┌───────────────────────────────────────┐
│ 3. 呈现给人，请求确认                  │
│ 格式：决策点 + 候选内容                │
│ 人可修改 / 拒绝 / 要求重写（含 keywords）│
└───────────────┬───────────────────────┘
                │ 人确认
                ▼
┌───────────────────────────────────────┐
│ 4. 写入文件 + 更新索引                 │
│ - 写入 docs/{file}.md                 │
│ - 在 TAGS.md 注册新标签（如需要）      │
│ - 更新 INDEX.md（含 Keywords 列）      │
│ - 更新 TAGS.md Count                  │
│ - 调用 knowledge_index_file() 增量索引│
└───────────────┬───────────────────────┘
                │
                ▼
┌───────────────────────────────────────┐
│ 5. 海马体记录                         │
│ 写入 maintenance_checklist             │
│ 「已向 References 写入 X 领域」         │
│ 备注：keywords 已配置                  │
└───────────────────────────────────────┘
```

## QG-3 Frontmatter 必填字段

每个 `docs/*.md` 文件必须以 YAML frontmatter 开头：

```yaml
---
title: '文档标题'
tags: [tag1, tag2]
keywords: ['关键词1', 'keyword2', '同义词3']
added: YYYY-MM-DD
source: '来源描述（URL / 模型名 / 实测 / 论文引用）'
credibility: 5
verified: false
reviewed_by: null
supersedes: null
superseded_by: null
---
```

### 字段定义

| 字段            | 类型         | 必填 | 说明                                      |
| --------------- | ------------ | :--: | ----------------------------------------- |
| `title`         | string       |  ✅  | 文档标题                                  |
| `tags`          | string[]     |  ✅  | 标签列表，必须在 TAGS.md 中已注册         |
| `keywords`      | string[]     |  ✅  | 检索关键词（5-15 个，中英双语），见 QG-11 |
| `added`         | date         |  ✅  | 首次写入日期 (YYYY-MM-DD)                 |
| `source`        | string       |  ✅  | 知识来源                                  |
| `credibility`   | int (1-10)   |  ✅  | 可信度评分，见 QG-4                       |
| `verified`      | bool         |  ✅  | 是否经人工验证                            |
| `reviewed_by`   | string\|null |  -   | 验证人标识                                |
| `supersedes`    | string\|null |  -   | 取代的旧文档文件名                        |
| `superseded_by` | string\|null |  -   | 被哪个文档取代                            |

---

## QG-4 Credibility 评分量表 (1-10)

| 分值 | 可信度   | 含义                     | 典型来源                           |
| ---- | -------- | ------------------------ | ---------------------------------- |
| 1-2  | 不可信   | 已知有误或严重过时       | 被证伪的博客、已废弃的 API 文档    |
| 3-4  | 低可信   | 缺乏验证，可能存在错误   | 无来源的个人观点、未验证的 AI 生成 |
| 5-6  | 中等可信 | 逻辑自洽，但未经独立验证 | AI 生成但逻辑自洽、单一非权威来源  |
| 7-8  | 高可信   | 来源权威或经人工验证     | 官方文档、权威教材、经人工确认     |
| 9-10 | 极高可信 | 多源交叉验证 + 实测确认  | 官方文档 + 实测 + 同行评审一致     |

**初始值规则**：

- AI 生成且未验证：默认 **5**
- 从官方文档转录：默认 **7**
- 从实测/项目经验提炼：默认 **6**（取决于验证程度）

---

## QG-5 编号约定

1. 本规范中所有规则以 `QG-{序号}` 编号
2. 新增规则时追加 `QG-N+1`，**不重新编号已有规则**
3. 在讨论/决策中引用规则时，使用编号引用（如「按 QG-4，此来源 credibility 应为 7」）
4. `QG-{序号}` 编号不可重用，即使某规则被废弃

## QG-6 冲突处理

### 6.1 整体过时（文档级别）

当新文档整体取代旧文档时：

- 新文档 `supersedes: "旧文件名.md"`
- 旧文档 `superseded_by: "新文件名.md"`
- 旧文档保留在原位置，credibility 降为 1

### 6.2 局部矛盾（段落级别）

当文档内某条信息与其他来源矛盾时，在文件中标注分歧：

```markdown
> ⚠️ 分歧 (QG-6.2)
> 源 A: O(n²) — credibility 5 (AI 生成, 2024)
> 源 B: O(n log n) — credibility 8 (官方文档 + 实测, 2026)
> 当前采纳: 源 B（更新 + 有实测数据）
```

### 6.3 无法判断

当矛盾无法通过现有信息解决时，标注：

```markdown
> ⚠️ 待确认 (QG-6.3)
> 源 A vs 源 B 存在矛盾，当前无足够信息判断。
> 等待更多验证数据后更新。
```

## QG-7 文件大小限制

| 指标     | 阈值             | 触发动作                                                        |
| -------- | ---------------- | --------------------------------------------------------------- |
| 行数     | > 400 行         | 在文档顶部标记 `⚠️ oversized`，提示应拆分子领域                 |
| 字数     | > 10,000 字      | 同上                                                            |
| 子主题数 | > 5 个独立子领域 | **强制拆分**：拆出子文档，原文档用 `superseded_by` 指向各子文档 |

### 拆分规则

1. 原文档保留为概览/索引角色，内容精简为摘要 + 指向子文档的链接
2. 子文档按子领域命名：`{tag}_{subdomain}.md`
3. 子文档继承原文档标签 + 追加细分标签
4. 原文档 `superseded_by` 列多个子文档文件名

## QG-8 文件命名约定

```
格式：{tag}_{topic}.md
分隔符：_（下划线）
规则：取最核心的 tag 作为前缀，文件跨多个 tag 则取最特化的 tag

示例：
  ios_swift-coding-standards.md     ← ios tag
  flutter_animations.md              ← flutter tag
  graphics_ray-tracing.md            ← graphics tag
  global_ai-toolchain.md             ← global tag
```

### 例外：保留嵌套结构的目录

当文件数量大且具有天然层级时（如组件库参考），可保留子目录：

- `docs/tdesign/` — TDesign 组件库（保留 miniprogram/ 和 miniprogram-chat/ 子结构）

## QG-9 标签注册规范

1. 新增标签必须先在 `TAGS.md` 注册，再在文档 frontmatter 中使用
2. 注册时填写：Tag 名、Description、First Used 日期
3. `Count` 和 `Last Reviewed` 在统一审查时批量更新
4. 发现未注册标签时，标记为异常并补充注册

---

## QG-10 编号引用规范

在讨论和决策中引用文档内容时，使用以下层级引用格式：

```
# 引用优先级
1. QG-{N} — 引用质量门规则
2. 2.{N} — 引用本文档的二级标题下第 N 项
3. 3.{N} — 引用本文档的三级标题下第 N 项
```

示例：

- 「按 QG-4，此来源 credibility 应为 7」
- 「按 QG-6.2，此处需要在文件中标注分歧」
- 「按 QG-7 行数限制，该文档已 420 行，需要拆分」
- 「按 QG-11，keywords 需要补充中文同义词」

## QG-11 Keywords 填写规范

### 11.1 用途

`keywords` 字段用于增强 INDEX.md 的检索能力，帮助 Agent 在 Step 3 做语义对齐时匹配到正确的文档。同时也是 Phase 2 向量检索的辅助元数据。

### 11.2 填写规则

| 规则 | 说明                                         |
| ---- | -------------------------------------------- |
| 数量 | **5-15 个**                                  |
| 语言 | **中英双语覆盖**（至少各 3 个）              |
| 内容 | 核心概念 + 常见同义词 + 口语化表达           |
| 格式 | YAML 数组 `['a', 'b', 'c']`                  |
| 禁止 | 堆砌无关词；单一语言；与 title/tags 完全重复 |

### 11.3 示例

```yaml
# ✅ 正确：中英双语，覆盖同义词和口语化表达
keywords: ['深色模式', 'dark mode', '主题切换', 'ColorScheme', 'trait collection', '日夜间', 'appearance', '暗黑模式']

# ✅ 正确：技术术语 + 口语化
keywords: ['Riverpod', '状态管理', 'state management', 'Provider', 'Notifier', '数据流', 'data flow', '响应式', 'reactive']

# ❌ 错误：只有英文
keywords: ['dark mode', 'ColorScheme', 'trait collection']

# ❌ 错误：只有中文
keywords: ['深色模式', '主题切换', '日夜间']

# ❌ 错误：太少
keywords: ['dark mode']

# ❌ 错误：堆砌无关词
keywords: ['iOS', 'Swift', 'Apple', 'iPhone', 'iPad', 'Mac', '开发', '编程', '代码']
```

### 11.4 与 INDEX.md Keywords 列的关系

| 位置                   | 用途                         | 维护方式            |
| ---------------------- | ---------------------------- | ------------------- |
| frontmatter `keywords` | 文档内自描述，供索引工具读取 | QG-2 写入时填写     |
| INDEX.md Keywords 列   | 集中索引，供 Agent 快速扫描  | QG-2 写入时同步更新 |

> 两者内容一致。INDEX.md 的 Keywords 列从 frontmatter `keywords` 字段同步。

### 11.5 演进路径

- **Phase 1**：keywords 主要供 Agent LLM 语义对齐使用（存在 INDEX.md 中）
- **Phase 2**：keywords 也作为 LanceDB 向量检索的 metadata filter，支持按关键词预筛选
